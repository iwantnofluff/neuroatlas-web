2What we need from the app team to move forward

  1. Auth provider. Which service handles login/identity across web and app (Supabase, Clerk, Firebase, etc.) — whatever the app already uses, plus dev and prod API keys once decided.
  2. Database access. Where user/pilot-status data lives, and the connection details the web app needs to read/write it — assuming the app's database becomes the single source of truth rather than us standing up a second one.
  3. Razorpay account. Sandbox/test RAZORPAY_KEY_ID and RAZORPAY_KEY_SECRET, and who owns webhook handling when a payment needs to unlock app features.
  4. App Store billing strategy. Whether the app is a "Reader App" (buy on web, log in on app) or offers native in-app billing alongside web billing — changes what the web checkout flow needs to do.
  5. Deep link config. Universal Links (iOS) and App Links (Android), for a post-purchase "Open in App" handoff.
